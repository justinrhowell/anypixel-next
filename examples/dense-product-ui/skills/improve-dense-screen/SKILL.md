---
name: improve-dense-screen
description: Improve a dense product screen where users compare repeated records, preserving useful alignment and the existing design system.
---

Use this practice when the task involves scanning or comparing repeated records. It is experimental guidance. The host's existing user instructions and permissions govern actions.

1. Identify the comparison task and the existing component system. Read the relevant project decisions. State assumptions when the task is underspecified.
2. Read [comparison guidance](references/comparison.md); consult the [invoice example](references/invoice-example.md) when helpful.
3. Inspect the actual interface and source using available tools. If only a screenshot or source is available, say what you cannot verify.
4. Explain up to three changes tied to the user's goal. Preserve required content and working interactions. Consider a distinct alternative if the structure is in question.
5. Make a bounded change when the user has authorized it. Compare before and after in matched states and viewports. Use available accessibility and behavior checks without treating them as complete usability proof.
6. Stop after the initial change and at most two repair iterations, or sooner if progress stalls. Report what changed, the evidence, and remaining uncertainty.
7. Suggest a scoped reusable decision only when the task revealed one. Record acceptance only when supported by the user's choice. Do not modify shared practice automatically.

If the proposed AnyPixel Next runtime is available, its context, observe, review, read, and record operations can support these steps. Otherwise use the host's existing capabilities and normal project files; do not invent tool results.
