# Preserve comparison before reducing density

**Status:** experimental. **Scope:** interfaces where people compare repeated records. **Evidence:** original illustrative guidance; no usability study has been run for this pack.

When the job is to compare dates, amounts, statuses, or owners across many records, first preserve common columns and stable alignment. Reduce competing emphasis, redundant labels, and low-value decoration before replacing a table with separate cards.

Describe which comparison the user needs to make. Identify the primary action and the information needed to make it. Reuse the product's existing table and type conventions. Preserve keyboard operation, understandable labels, and an approach for smaller viewports.

This guidance is insufficient when the task centers on rich per-item media, sequential storytelling, or actions requiring substantial item-specific context. It is also insufficient to establish accessibility: use appropriate checks and observe real interaction behavior.

A useful critique says: “The user needs to compare overdue amounts. Keeping amount and due date aligned helps that task; making every cell bold makes scanning harder.” It should not simply say “tables are better” or “dense is our brand.”

**Counterexample:** a photo-selection interface may need image-first cards. Do not apply the table recommendation solely because the screen contains many items.
